# 구조물 안정성 물리 추론 AI 경진대회 (Structural Stability Physical Reasoning)

> DACON 월간 데이콘 | 다각도 이미지 기반 구조물 안정성 예측

## 1. 프로젝트 개요

### 대회 목표
구조물을 두 시점(전면, 상단)에서 촬영한 이미지만 보고, 시뮬레이션 10초 동안 **불안정(unstable)해질 확률**과 **안정(stable)을 유지할 확률**을 예측하는 모델을 만드는 대회입니다. 평가 지표는 **Log Loss**입니다.

### 문제의 핵심
- 학습 데이터(1,000개)는 광원과 카메라 좌표가 **고정된 실험 환경**에서 생성되었습니다.
- 개발 데이터(100개)와 평가 데이터(1,000개)는 광원과 카메라 좌표가 **무작위로 변하는 실제 환경**입니다.
- 즉, 학습 환경에만 맞춘 모델은 평가 환경에서 성능이 떨어질 수 있어, **환경 변화에 대한 일반화**가 이 대회의 핵심 과제입니다.

### 데이터 구성

| 구분 | 샘플 수 | 환경 | 비고 |
|---|---|---|---|
| train | 1,000 | 광원·카메라 고정 | stable 500 / unstable 500 (균형) |
| dev | 100 | 무작위 변동 | 평가 환경과 동일 설정, 검증용 |
| test | 1,000 | 무작위 변동 | 최종 순위 기준 |

### 결과 요약
| 항목 | 값 |
|---|---|
| 검증(dev) 최고 Log Loss | **0.4973** (Epoch 5) |
| 해당 시점 검증 Accuracy | 0.79 |
| 리더보드 점수 / 순위 | (여기에 기입) |

## 2. 기술 스택

- **Language**: Python
- **Deep Learning**: PyTorch, torchvision (ImageNet 사전학습 ResNet18)
- **Data**: pandas, NumPy, Pillow
- **기타**: tqdm

## 3. 핵심 분석 프로세스

### 3-1. 데이터 확인
- 학습 데이터의 클래스 분포가 stable 500 / unstable 500으로 균형임을 확인했습니다.
- 샘플마다 `front.png`, `top.png` 두 장의 이미지를 입력으로 사용합니다.

### 3-2. 멀티뷰 입력 구성
- 커스텀 `Dataset`에서 샘플 폴더의 전면(front), 상단(top) 이미지를 함께 불러와 리스트로 반환합니다.
- 전처리: 224×224 리사이즈, ImageNet 평균·표준편차 정규화

### 3-3. 모델 설계 (Multi-View ResNet18)
```
front 이미지 ─┐
              ├─ ResNet18 (공유 백본) → 512차원 특징 ×2 → Concat(1024)
top 이미지  ──┘
        → Linear(1024→256) → ReLU → Dropout(0.2) → Linear(256→1) → Sigmoid
```
- 두 시점에 **같은 백본(가중치 공유)** 을 적용해 파라미터 수를 늘리지 않고 두 시점의 특징을 추출했습니다.
- 두 특징을 이어 붙여 하나의 분류기에 넣어, 서로 다른 시점의 정보를 함께 판단하도록 했습니다.

### 3-4. 학습 설정
| 항목 | 설정 |
|---|---|
| Loss | BCEWithLogitsLoss |
| Optimizer | AdamW (lr 1e-4, weight decay 1e-2) |
| Scheduler | CosineAnnealingWarmRestarts (T_0=5) |
| 안정화 | Gradient Clipping (max_norm=1.0) |
| Epoch / Batch | 20 / 32 |
| Seed | 42 (재현성 고정) |

### 3-5. 평가와 모델 선택
- 대회 공식 지표인 **Log Loss를 직접 구현**하여 검증에 사용했습니다. 확률을 `[1e-15, 1-1e-15]`로 클리핑하여 수치 오류를 방지했습니다.
- Accuracy를 함께 기록하되, **검증 Log Loss가 가장 낮은 Epoch의 가중치**를 저장해 추론에 사용했습니다.

### 3-6. 추론
- 저장된 best 모델로 test 이미지의 `unstable_prob`를 계산하고 `stable_prob = 1 - unstable_prob`로 제출 파일을 생성했습니다.

## 4. 깨달은 점

### 확인한 것
1. **학습 환경에 과적합되는 현상을 직접 확인했습니다.**
   학습 Loss는 Epoch 2부터 0.002 이하, 이후 0.0001 수준까지 떨어졌지만, 검증 Log Loss는 0.50~1.00 사이에서 크게 흔들렸습니다. 대회 설명에서 경고한 "고정된 환경에 대한 과적합"이 실제로 나타났습니다.

2. **Accuracy보다 Log Loss가 더 엄격한 지표입니다.**
   검증 Accuracy가 0.74~0.79로 비슷해 보여도 Log Loss는 크게 달랐습니다. 틀린 예측에 높은 확신을 줄수록 손실이 커지므로, 확률의 보정(calibration)이 중요함을 알게 되었습니다.

3. **검증 데이터가 100개로 적으면 Epoch별 성능이 불안정합니다.**
   best Epoch를 고르는 기준 자체가 노이즈의 영향을 받아, 한 번의 검증 결과를 과신하기 어렵다는 점을 배웠습니다.

### 아쉬운 점
- 코드에는 데이터 증강 자리가 있었지만 **실제 증강은 적용하지 못했습니다.** 학습과 평가 환경이 다른 대회에서 가장 먼저 시도했어야 할 부분입니다.
- 제공된 10초 시뮬레이션 영상은 활용하지 못했습니다.
